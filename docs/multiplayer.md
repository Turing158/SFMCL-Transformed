# 联机

更新：2026-11-12。联机方式可选择「Cloudflare Tunnel + 本机EasyTier」自动开房，或「共享EasyTier节点」并填写指定节点地址。跨网络双机和真实 Minecraft 进世界仍需实机验收。

## 使用

「联机」位于主菜单「版本管理」下方，与「开始游戏」使用相同的独立页面。左侧创建／加入或当前房间，右侧教程，下方当前角色与版本；说明集中在教程中。

房主先启动 Minecraft Java，进入存档并「对局域网开放」，填写房间名称和聊天栏端口后创建。「联机方式」默认选择「Cloudflare Tunnel + 本机EasyTier」，仅显示选择框；启动器自动准备 EasyTier 和 cloudflared，启动本机节点及临时隧道，校验公网 WebSocket 入口后允许复制完整邀请码。选择「共享EasyTier节点」后，选择框收窄到右侧，左侧出现节点地址输入框，必须填写 `tcp://主机:端口` 或 `udp://主机:端口`；此模式使用指定节点，不启动 Cloudflare Tunnel，空白地址不能创建。切回自动模式时保留地址草稿，但不会随创建请求提交。自动模式无需 Cloudflare 账号、域名、公网 IP 或路由器端口映射。「准备组件」和「导入组件」仍用于 EasyTier 官方 v2.6.4 对应架构 ZIP；自动模式创建时补齐隧道组件。

组件准备统一在「下载中心」显示操作步骤和文件下载任务，联机页保留房间表单，不再显示独立的组件进度卡片。下载可暂停、继续、失败重试或取消；重试成功后自动校验并安装，创建／加入过程中触发的准备会接着完成房间连接。导入和已有组件校验同样记录为操作任务。取消操作或退出启动器会先停止下载写入，再释放本次临时归档；已安装组件保留。

创建房间优先使用本启动器实际启动的游戏，自动沿用启动时的角色、基础版本与游戏实例，不受之后切换角色、版本或游戏目录影响。只有一个游戏时自动识别；有多个实例时，优先识别唯一已运行的游戏，否则通过「房主游戏」选择。正在准备资源的游戏会显示启动信息，完成启动并开放世界后才能创建。提交时由后端重新核对实例仍在运行，已结束的实例不能继续创建。没有可识别的实例时，仍可沿用角色管理和版本管理中的当前选择，为已手动开放的世界创建房间。游戏端口仍需填写，联机入口由启动器自动生成。

好友粘贴邀请码，查看房间、基础游戏版本和联机入口，再加入。好友仅使用 EasyTier，不需要安装或配置 cloudflared。世界就绪后选择匹配的版本、加载器、模组和角色，点击「启动并连接」。已有游戏在运行时使用「复制地址」，在多人游戏中直接连接本机地址。

- 邀请包含房间凭据，只分享给参与者。关闭后重新创建会换新凭据；端口改变须重新创建。没有短码查询服务或单成员撤销功能。
- 成员表示网络节点，不代表玩家已进入世界。直连／中继／隧道和延迟来自引擎。版本不一致会在启动前确认；账号认证和模组握手仍由 Minecraft 完成。
- 切页、最小化及托盘隐藏保持连接。离开房间断开网络，不结束 Minecraft。真正退出启动器会提示并清理网络进程。
- 世界关闭后禁用启动及分享；同端口恢复后自动恢复可用状态。失败后可重新提交创建／加入；连接尚未成功时保留邀请码草稿以便重试。

## 自动联机入口

选择「Cloudflare Tunnel + 本机EasyTier」时，房主的 EasyTier 仅监听随机回环地址 `ws://127.0.0.1:<端口>`。本机 cloudflared 使用显式空配置和独立工作目录，将这一 WebSocket 监听器接到随机 `trycloudflare.com` 域名。好友根据邀请码里的 `wss://<随机域名>.trycloudflare.com` 直接连接同一房间。

自动模式邀请码使用 `SFMCL2.`，携带公开入口和房间凭据。地址取得、隧道连接及 TLS / WebSocket 握手校验完成前不能分享；房主独自开房即可就绪，不需要先有好友连接。为避免依赖 NAT 打洞，自动模式通过隧道传输。Minecraft 世界仍运行在房主电脑上。

Cloudflare Quick Tunnels 面向测试和开发，没有在线时长或可用性保证。每次开房会取得新的入口；关闭房间、真正退出启动器或宿主被终止时，本实例的两个网络进程均被释放。仍存活的隧道在网络恢复时自动重连；隧道进程退出则需要重新创建房间。服务限制见 [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。

选择共享节点模式并填写地址时生成 `SFMCL1.` 邀请，仍可加入此前的 TCP / UDP 邀请。节点地址会随邀请码交给好友，需双方可访问；直连失败时需要节点支持中继。联机方式和输入内容在切页后保留，仅存在本次启动器运行的内存中，不写入设置。自建公共共享节点配置参考 [节点配置](examples/easytier-shared-node.toml)：

```sh
easytier-core -c easytier-shared-node.toml --disable-env-parsing
```

默认开房不使用该共享节点配置，也不需要手动部署公网服务器。

## 实现与边界

采用 no-TUN + smoltcp TCP 代理，不安装虚拟网卡、WinDivert／Npcap 驱动，不配置系统路由、DNS、UPnP 或防火墙规则。虚拟地址只在引擎中使用，房间网段随机生成，房主地址固定为该网段的 `.1`，好友通过引擎 DHCP 处理地址分配和冲突。

房主只允许访问选定游戏端口。好友默认拒绝入站／转发，仅允许到房主游戏端口的状态跟踪 TCP 出站。好友连接入口绑定 `127.0.0.1`，不会在物理局域网公开监听。RPC 绑定随机回环端口，并设置回环白名单；本机同用户进程并不属于该 RPC 的隔离边界。

邀请码严格限制版本、长度、字段、端口和节点协议，不接受任意配置或命令参数。凭据不落盘，通过匿名管道送入引擎，关闭原始引擎日志。前端只在复制时请求邀请，不写入 localStorage 或设置。状态与成员是脱敏快照。

后端每实例只允许一个会话，处理准备、连接、就绪、等待世界、取消、失败和退出；页面隐藏不停止后台检测。每次就绪要求收到有界的 Minecraft 状态响应，不以转发端口接受 TCP 代替世界可用。临时入口创建最多等待 90 秒，随后首次房间连接 45 秒无成功则失败；活动房间持续检查世界和本机隧道健康状态并等待恢复。

EasyTier 和 cloudflared 创建时即加入 Windows kill-on-close Job Object。取消、退出、启动器被终止都会释放本实例进程，不能接管用户自己的 EasyTier 或 cloudflared。数据迁移、备份、还原与活动会话互斥。邀请码的原始内容、游戏流量和网络密钥不会进入任务日志。

联机启动只接收会话 ID，由后端取得本次有效的回环目标，复用账号认证、版本锁、下载任务、Quick Play／旧版 `--server --port` 和启动后窗口行为。在准备资源之后再次检测世界及会话有效性。全局和版本设置不会写入房间地址。

## 固定组件与分发

引擎：[EasyTier v2.6.4](https://github.com/EasyTier/EasyTier/releases/tag/v2.6.4)，源码 `8428a89d2dabc94c97d370ec607c6ca142473626`，LGPL-3.0。下载时核对完整大小、ZIP SHA-256 以及两个可执行文件各自的 SHA-256；每次启动再次验证已安装文件。只读取归档内固定成员，不解压用户路径。

| --- | ---: | --- |
| easytier-windows-x86_64-v2.6.4.zip | 32657720 | `27af91e270e554709b048bd32327fefd2dfce5062ae1e8701af7550c6f525f84` |
| easytier-windows-i686-v2.6.4.zip | 30881261 | `bf557daeccc5525d95b8a230c339d75554fb52d82d1e050e9a5202c92c02e09e` |

EasyTier 组件位于应用数据目录 `multiplayer/easytier-2.6.4-<架构>/`。房主使用的 cloudflared 固定为 [2026.10.7](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.7)，按需下载至 `multiplayer/cloudflared-2026.10.7-<架构>/`；安装和每次开房均校验官方 SHA-256。amd64 EXE：55390512 字节，`2493dbc168923bb3e59e5e7716f71deced92992eea9acd6e9d74f84ac7751343`；386 EXE：38097032 字节，`88c6b972b410db0e26745f593510d772c825a13c5a2374819e3f13a05b333082`。Apache-2.0 许可证随组件写入。下载中断可重试；临时文件随操作取消或结束释放。活动房间期间禁止替换组件。

官方 Windows EXE 依赖 Packet.dll，但归档所带的 Npcap DLL 不适合直接随本项目再分发。客户端不提取它，改为内嵌并校验 WinPcap 4.1.3 的 BSD 许可兼容 DLL。两个架构均通过实际启动和网络转发测试。只加载兼容库，未安装旧驱动；不启用抓包功能。来源、文件哈希、上游源码、LGPL/GPL 及 WinPcap 声明见 [NOTICE](../SFMCL-T/licenses/easytier/NOTICE.txt) 及同目录许可证。组件准备时同时写入这些声明。以后如要离线重分发 EasyTier 本体，需同时满足对应源码交付要求。

## 验证

真实引擎测试使用官方 Windows EXE、兼容 DLL、独立本机共享节点与 Minecraft 状态协议夹具，已验证：

- 直接 TCP 转发和强制中继转发，分别核对引擎报告 `p2p` / `relay(...)`。
- 主机与好友均拒绝对另外一个真实监听服务的访问；攻击方移除了自身 ACL，并核实目标为远端节点。
- 房主独自连接节点即可就绪并分享，好友加入并取得本次启动目标，关闭世界后禁用目标，退出后旧启动凭据失效。
- 取消、重复操作、过期会话、数据维护互斥、邀请码非法输入、篡改归档拒绝、临时启动设置不写回。
- 强制终止测试宿主进程后，Windows Job 自动结束其网络引擎；所有测试自建进程与临时目录均释放。
- 真实 Cloudflare Quick Tunnel + 两个 EasyTier 实例通过 `SFMCL2.` 邀请连接，核对 `wss` 隧道路由并转发 Minecraft 状态；房主独自就绪、关闭世界禁用分享／启动、离开房间释放两个进程及隧道工作目录均通过。该测试使用同一电脑上的两个实例和状态协议夹具，不等同于跨网双机或真实玩家进入世界。

运行方式（仓库内 `SFMCL-T/`）：

```powershell
cargo test -p sfmcl-t-core multiplayer --lib
$env:SFMCL_EASYTIER_ZIP = '官方 x64 ZIP 的绝对路径'
$env:SFMCL_CLOUDFLARED_EXE = '官方 cloudflared 2026.10.7 amd64 EXE 的绝对路径'
cargo test -p sfmcl-t-core real_cloudflare_invitation_and_lifecycle --lib -- --ignored --nocapture
cargo test -p sfmcl-t-core real_engine_relay --lib -- --ignored --nocapture
# 在 x64 Windows 上运行 x86 引擎兼容性测试：
$env:SFMCL_EASYTIER_ZIP = '官方 i686 ZIP 的绝对路径'
$env:SFMCL_EASYTIER_ARCH = 'x86'
cargo test -p sfmcl-t-core real_engine_relay --lib -- --ignored --nocapture
```

`npm run test:multiplayer` 在 Vite 1421 端口上验证组件准备保留房间表单、下载中心任务及暂停／继续／失败重试／取消、导入组件任务、准备后继续创建／加入、邀请预览、复制、启动请求、世界关闭、切页保留、暗色与窄布局。浏览器使用内存 Tauri 夹具，不替代桌面或网络验收。

| 范围 | 本次结果 |
| --- | --- |
| x64 Windows 上 x64 / x86 引擎 | 真实直连、中继、双方 ACL、崩溃清理通过 |
| x64 Windows 上 Cloudflare 公网 WSS 入口 | 官方 cloudflared + 两个真实引擎、邀请码、状态转发及退出清理通过 |
| 客户端核心／前端 | 单元、真实引擎集成、界面交互及构建验证 |
